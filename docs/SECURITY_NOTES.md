# Безопасность и секреты

## Правило

В репозитории не должно быть токенов, паролей, keystore и `.env`. Всё, что нужно
CI, хранится в GitHub Actions Secrets. `.env`, `.env.*`, `*.keystore`,
`export_credentials.cfg` и `*.ps1` перечислены в `.gitignore`.

## Инцидент с `.env`

В ранней истории репозитория (коммиты `0341e96` → `6d38274`) существовал файл
`.env` (56 байт) с GitHub-токеном. Файл был удалён из рабочего дерева, но
оставался доступен в истории.

Что сделано:

1. `.env` удалён из рабочего дерева и из reachable-истории: `main` заменён одним
   корневым коммитом `f66eed9` (полную старую историю не удалось вычитать из-за
   сетевых ограничений, поэтому rewrite выполнен через чистый корень — дерево
   файлов при этом актуальное).
2. Force-push выполнен: `main` и тег `v0.0.4` на GitHub указывают на новую
   историю. Старые коммиты (`22ce6c8` и ранее) больше не достижимы по refs, но
   GitHub может отдавать их по SHA до сборки мусора.
3. `.env` отсутствует в рабочем дереве; добавлены проверки в тестах.

Что должен сделать владелец:

- [ ] **Отозвать и перевыпустить токен** — это главная мера; удаление файла и
      force-push её не заменяют (старый SHA может быть доступен по прямой ссылке).
- [ ] Попросить участников переклонировать репозиторий (история заменена).
- [ ] Проверить GitHub → Settings → Sessions/Applications на подозрительную
      активность.
- [ ] Включить secret scanning и push protection, если доступны.

## Проверка после изменений

```powershell
git log --all -- .env          # должно быть пусто
git grep -n "ghp_\|github_pat_" $(git rev-list --all)  # при наличии полной истории
python -X utf8 -m unittest discover -s tests -p "test_*.py"
```
