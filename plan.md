## 1. Что это за проект

**Semey Car Driving / Semey Drive** — мобильная автомобильная игра на Godot 4.7
про город Семей (Казахстан). Изначально это был атмосферный free-roam с
OSM-городом, дрифт-очками и гаражом (версия 0.0.4). После ревью владелец решил
**переработать игру** в сторону жанра Car Parking Multiplayer / Caucasus Parking:
реалистичная картинка, парковочная физика, понятный мобильный UI, узнаваемый
город.

Сейчас идёт **M1 — вертикальный срез**: мост через Иртыш и набережная, Приора,
день, две камеры, HUD, меню. Без заданий, экономики, мультиплеера и пешего
режима.

Репозиторий: <https://github.com/ryouta-dev/SemeyCarDriving>

## 5. Архитектура

```

scenes/
  menu.tscn                  → scripts/ui/menu_m1.gd
  showcase_bridge.tscn       → scripts/world/showcase_zone.gd
  garage.tscn, main.tscn, test_track.tscn   legacy 0.0.4 (не ломать)
scripts/
  ui/menu_m1.gd              меню: сцена, свет, Приора, кнопки
  ui/hud_m1.gd               HUD: ввод, пауза, камеры, свет, P/R/N/D
  ui/speedometer_m1.gd       круглый спидометр (draw)
  ui/minimap_m1.gd           схема моста/реки/машины (draw)
  ui/theme_m1.gd             палитра, панели, кнопки, SystemFont
  ui/virtual_steering_wheel.gd  руль (2D, будет заменён 3D-рулём Приоры)
  camera/vehicle_camera_rig.gd  chase + cockpit, collision, FOV
  world/showcase_zone.gd     сборка мира, река, берега, город, машина, свет
  world/bridge_builder.gd    мост: деки, пилоны, ванты, ограждения, разметка
  vehicle/drive_controller.gd  связка HUD ↔ GEVP: руль, газ/тормоз, P/R/N/D
  audio/ambience_m1.gd       ветер/вода (процедурные WAV)
  quality_settings.gd        пресеты + SSAO/SSR/fog/glow
  tuning/vehicle_tuning_applicator.gd  визуал/физика авто, owner=null, low-GLB
addons/gevp/                 физика (форк Godot Easy Vehicle Physics)
data/                        OSM + VehicleDefinition (.tres)
tests/                       Python + runtime_tests.gd + m1_capture.gd
tools/                       generate_ambience.py, check_assets.py, bake_osm_tiles.py
docs/                        REWORK_M1.md, TESTING.md, REMAINING.md, ASSET_LICENSES.md
```

**Потоки:**
- `menu_m1.gd` строит сцену и по «ИГРАТЬ» делает `change_scene_to_file("res://scenes/showcase_bridge.tscn")`.
- `showcase_zone.gd` вызывает `BridgeBuilder.build()`, создаёт машину (`simcade_car.tscn` + `VehicleTuningApplicator` с Приорой), камеру, HUD, контроллер, звук.
- `HUDM1` читает ввод (тач + клавиатура) → `DriveController` пишет в `Vehicle` (GEVP) → камера и спидометр читают состояние.
- `QualitySettings.apply(viewport, preset)` ищет ноду в группе `quality_environment` и включает/выключает SSAO/SSR/fog/glow.

**Сделано в M1.1 (второй проход):**

- Приора: светящиеся плёнки стопов/габаритов и фар (`CarDetails.attach_light_lenses`),

- `tests/m1_capture.gd` снимает третий кадр — набережную и пирс;
- CI на GitHub теперь запускается и на push в `rework/m1`.

**Исправлено после теста владельца (2026-10-24):**
- вылет/зависание при нажатии «N» и «R»: переключение P/R/N/D больше не крутит
  `Vehicle.shift()` в цикле, а ставит передачу мгновенно
  (`Vehicle.set_gear_instant`); в runtime-тестах появились проверки N/R/D;
- «красные квадраты» у стопов убраны: свечение теперь идёт от собственного
  материала оптики модели (`priora_optik_rear`), а не от накладных плёнок;
- посадка Приоры: сцена больше не берёт сохранённый профиль 0.0.4 (там была
  экстремальная заниженная подвеска и свап V8) — машина стоит на колёсах,
  кузов поднят (`visual_offset` −0.29 → −0.05);
- свободный обзор камерой: зажать ЛКМ/ПКМ и вести мышью, на телефоне — свайп
  пальцем; при отпускании камера возвращается в центр;
- меню показывает карточку «ЗАГРУЗКА…» перед переходом в сцену — фриз на
  построении мира больше не выглядит как зависшее чёрное окно.

**Сделано в M1.1 (третий проход — материалы и свет):**
- свет: солнце 2.2 → 1.6, ambient 1.0 → 0.55, exposure 0.92, ACES плюс
  коррекция (контраст 1.08, насыщенность 1.12), туман реже и холоднее,
  добавлено рассеяние солнца в дымке; SSAO и тени усилены — картинка перестала
  быть белёсой;
- небо: глубже синий зенит, светлее горизонт, облака чуть реже;
- вода: шейдер переписан — крупная зыбь, три частоты ряби, затухание деталей по
  дистанции (против мерцания), fresnel-смесь цвета и отражений, солнечные блики;
- земля и бетон: процедурные текстуры травы, бетона променада, каменной
  облицовки и асфальта; асфальт моста чуть светлее;
- берег: камни по линии воды вдоль набережной.
- трафик: вместо одной коробки — три типа кузова (седан, хэтчбек, универсал),
  стеклянная кабина с крышей, бамперы, диски; колёса утоплены в габарит.
  Скачать CC0-модель машины не удалось: Poly Pizza и Kenney отдают файлы только
  через интерактивную загрузку в браузере. Для тестового полигона примитивов
  достаточно; если владелец принесёт GLB — заменим одной строкой в `_spawn_car`.

Следующее по замечаниям владельца: **«угловатость» больше не приоритет** —
владелец решил, что полигон не нужно доводить до красоты, важнее другие части
(ощущение езды, HUD/настройки, звук).

## 7. Как запускать и проверять

```powershell
$godot = 'C:\Users\elzha\Desktop\Godot_v4.7.2-stable_win64_console.exe'

# 1. Импорт (после новых сцен/скриптов)
& $godot --headless --path . --editor --import --quit

# 2. Godot runtime-тесты
& $godot --headless --path . --audio-driver Dummy --script res://tests/runtime_tests.gd

# 3. Python-тесты (Windows: UTF-8 обязателен)
$env:PYTHONUTF8 = '1'
python -X utf8 -m unittest discover -s tests -p "test_*.py"

# 4. Скриншоты меню и моста (без --headless, нужен GPU)
& $godot --path . --audio-driver Dummy --script res://tests/m1_capture.gd

```

Игра вручную: `& $godot --path .` (F5). В меню Enter = играть, Esc = выход.
В игре: WASD, Space, C — камера, L — свет, Esc — пауза, R — сброс машины.

## 8. Git и грабли

### Ветки
- Работать **только** в `rework/m1`; `main` — стабильная 0.0.4.
- Перед началом: `git checkout rework/m1 && git pull origin rework/m1`.
- Коммит/пуш: `git add -A && git commit -m "..." && git push`.

### История
- `main` — **новый корневой коммит** после удаления `.env` из истории; тег `v0.0.4`.
- Старые SHA могут ещё отдаваться GitHub по прямой ссылке, токен всё равно нужно
  отозвать. См. `docs/SECURITY_NOTES.md`.
- Не делать force-push без бэкапа.

### Partial clone
Репозиторий когда-то клонировался с `--filter=blob:none`, промисор-конфиг снят,
все блобы записаны локально. Если git внезапно лезет в сеть и зависает —
использовать `$env:GIT_NO_LAZY_FETCH='1'` и не запускать `git fetch` без нужды.

### Кодировка (важно)
**Не перезаписывать файлы с кириллицей через `Get-Content | Set-Content`** в
PowerShell: UTF-8 читается как ANSI и текст превращается в `РџСЂ...`. Для правок
использовать инструменты `edit`/`write` или Python с `encoding="utf-8"`.

### Ассеты
- `*_rigged_Image_*.png` в корне — **нужны**: Godot извлёк их из GLB, `.scn`
  ссылается на них. Удаление ломает Приору/Ладу.
- `priora_steer_47` в GLB — **пустой Node3D без мешей**. 3D-руль из него не
  собрать; руль влит в панель. Используем улучшенный 2D-руль.
- `source_assets/` — исходники, исключены `.gdignore`; в экспорт не попадают.
- Права на модели авто — RED (`docs/ASSET_LICENSES.md`). Для локального
  прототипа ок, для публичного релиза нужна замена.
- Новые ассеты — только CC0/OFL/Apache. Складывать в `sounds/`, `assets/`,
  `scenes/models/`; добавлять в реестр лицензий.

### Тесты
- Python-тесты читают исходники; любой новый `.gd` с `class_name` должен иметь
  уникальное имя (проверка дублей).
- `tests/test_assets.py` требует, чтобы каждый бинарный ассет был в реестре.
- `runtime_tests.gd` ждёт асинхронный спавн через `_wait_until`; фиксированные
  кадры не использовать.
- Headless-тесты не проверяют картинку; для визуала — `m1_capture.gd`.

### 14.5 Грабли (важно)
- **Новый скрипт с `class_name` требует импорта**: без
  `godot --headless --path . --editor --import --quit` headless-тесты падают с
  «Identifier ... not declared», а сцена грузится пустым `Node3D`.
- **Не использовать `vehicle.freeze` для P/N** — замороженный `RigidBody`
  подпрыгивает при разморозке. P = обычный тормоз.
- P/R/N/D переключать через `Vehicle.set_gear_instant()`, а не циклом `shift()`.
- Замеры физики и камеры — временным скриптом `tests/_tmp_*.gd`:
  инстанцировать `scenes/showcase_bridge.tscn`, отключить
  `zone.controller.set_physics_process(false)`, шагать `await physics_frame`
  (или `process_frame`), печатать числа, потом удалить файл.
- Для проверки дрожания камеры: `--fixed-fps 144` (рендер 144 при физике 120).
- Кириллицу писать только инструментами `edit`/`write`, не PowerShell.
- Перед коммитом: импорт → runtime-тесты → python-тесты → скриншоты.
